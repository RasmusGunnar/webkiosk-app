# Internationalization 1.0 · local review

Native / Subscription / Wall 5.0 is retained on `feature/native-subscription-wall`. No hosted migration, Edge deployment, Vercel deployment, store action, commit or push is part of this task.

## UI and family data

`app/src/i18n/index.js` owns i18next, locale choice, fallback, Intl formatters and preference persistence. Separate `da-DK.json` and `en-GB.json` catalogs use semantic keys. Components explicitly call `t`; there is no runtime string replacement or DOM translation pass. `domain-labels.js` translates persisted enum values only at display boundaries. Saved event/task/recipe/shopping titles, notes, person names and household names remain untouched. Generated milestones have stable IDs and locale-specific display titles; matching legacy milestones still uses the original aliases.

Both catalogs are bundled for immediate offline switching. Additional languages require adding a catalog, the supported locale list and preference constraints, without duplicating product components. Missing translations fall back to Danish; unknown keys display a safe generic message. Catalog parity, duplicate keys, references and a targeted AST hardcoded-UI guard run with `npm --prefix app run check:i18n`. Intentional exclusions are persisted domain values, source-data aliases, identifiers, brand/platform names and the DEV-only native provider fixture.

iOS camera/photo permission descriptions have Danish and British English `InfoPlist.strings` resources. The OS selects permission-dialog language through its app/system language; the in-app personal selector controls the web UI. Android has no custom permission prose and keeps the unchanged app name. Real OS permission dialogs still need native device verification.

## Preferences and currency

First use maps Danish system locales to Danish, other available system locales to English, and a missing locale to Danish. Explicit per-user local preference and `profiles.preferred_locale` survive reload. Profile preference wins across devices. Offline selections queue locally and retry when reconnecting. No sign-out is needed.

Settings → Account contains the personal selector. Settings → Family lets an owner/admin select the family's default language and ISO currency. Family → Devices contains an independent per-display selector. A null display locale follows the family; pairing defaults to this behavior. Wall snapshots include only the existing safe projection plus default locale/currency. Changing an adult's personal locale does not change the display.

Existing households default to `da-DK` and `DKK`. Supported currencies: DKK, EUR, SEK, NOK, GBP, USD. Amounts remain unchanged in minor units: changing currency is an explicit display/accounting preference, **not conversion**. RevenueCat product text and localized prices remain provider data. Locale and `Europe/Copenhagen` timezone are separate. Computational civil-date formatters remain invariant; user-facing dates/times/numbers/currency use central Intl helpers. Count messages use i18next plural rules.

## Auth email and notifications

App invitation links are composed in the current UI locale; no app mail sender exists. New signups include `preferred_locale` in Auth metadata for later template selection. Profile language changes are authoritative for the app; existing Auth metadata should be synchronized by a future approved backend mail integration if used for hosted template routing. Do not assume updating the profile changes Auth metadata automatically.

`docs/auth-email-templates.html` is a local bilingual Supabase template draft. In a later explicitly approved Dashboard task, configure Authentication → Email Templates for confirmation, recovery, invitation and email change, review the final sender/support/legal information, and test both locale branches. Danish is the fallback for existing users without metadata. No hosted template has been changed. A template's confirmation URL must stay the Supabase-supplied value; never embed tokens or credentials in Git.

The app has native push registration/settings text but no notification delivery engine. Existing labels are translated; no push feature or provider setup was added.
